# Requirements: whatsapp-sync

**Defined:** 2026-07-13
**Core Value:** Reliable, unidirectional file transfers between WhatsApp and the local filesystem without complex bidirectional sync logic or race conditions.

## v1 Requirements

### Core Synchronization

- [ ] **SYNC-01**: `watcher.js` listens for messages in the "send me" WhatsApp group.
- [ ] **SYNC-02**: Incoming files in "send me" are downloaded to `Documents/syncstaging/in`.
- [ ] **SYNC-03**: Downloaded files are subsequently deleted from the WhatsApp group.
- [ ] **SYNC-04**: `watcher.js` monitors the `Documents/syncstaging/out` local folder.
- [ ] **SYNC-05**: Files placed in the `out` folder are uploaded to the "receive me" WhatsApp group.
- [ ] **SYNC-06**: Uploaded files are subsequently deleted from the local `out` folder.
- [ ] **SYNC-07**: Update existing `watcher.js` tests to cover these simplified flows.

## v2 Requirements

### Package Migration

- [ ] **PKG-01**: Remove all `whatsapp-web.js` library source files from the local repository to ensure it only contains `whatsapp-sync` code.
- [ ] **PKG-02**: Update `package.json` to declare `whatsapp-web.js` and other necessary libraries as NPM dependencies.
- [ ] **PKG-03**: Refactor `watcher.js` to import `whatsapp-web.js` normally instead of using local file paths.
- [ ] **PKG-04**: Use `patch-package` for any protocol-level modifications if necessary, replacing `patch_script.js`.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Bidirectional File Sync | Complex, unnecessary state management |
| Race Condition Handling | Simplified by distinct in/out pipelines |
| Changes outside `watcher.js` | Modifying the underlying library is forbidden |
